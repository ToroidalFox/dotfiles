## Interpreting user prompt

- A question is just a question. It should not be interpreted as an implied call to action.
- Unless the intent is obvious, resolve any ambiguity by asking clarifying question.

## Code style

- If a function's name and signature are verbose enough, keep its documentation very short.
- When writing documentation for code, keep the overview short. Then, include caveats, errors, platform-specific details, special cases, etc., under corresponding headings. Finally, provide examples that complement the usage guide.
